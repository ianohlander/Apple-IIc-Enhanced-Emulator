Readability & Pedagogical Clarity Evaluation

The audit evaluated the tutorial against three key educational standards: (1) Conceptual Context (explaining why a command exists before asking the user to type it), (2) Micro-Architectural Grounding (explaining memory addresses, opcodes, and hardware vectors rather than presenting magic values), and (3) Deterministic Feedback (showing exact expected CRT/terminal outputs and troubleshooting steps).

❌ Before Overhaul (Baseline Issues)
  • Opaque Commands: Labs listed bare hex bytes (e.g. 0300: 64 06 9C 00 08 60) with zero explanation of what opcodes were being deposited or why $0300 was chosen.
  • Assumed Retro Knowledge: Assumed users already knew decimal -151 mapped to $FF69 (Monitor ROM entry), or that 1024 was Text Page 1 Row 0 VRAM.
  • Missing Feedback Loops: No clear description of what the user should see on screen or how to recover if a syntax error occurred.
✅ After Overhaul (Current Standard)
  • "What You Are Doing & Why": Every single lab starts with a clear conceptual primer explaining the underlying hardware mechanism.
  • Line-by-Line Annotated Breakdowns: Assembly opcodes (e.g. STZ Store Zero, RTS Return), memory vectors, and ASCII calculations are exhaustively annotated.
  • Step-by-Step Guidance: Clear step numbers with exact keyboard inputs, expected prompt changes (] █ vs * █), and return sequences (3D0G).

Issues Identified, Root Causes & Fixes Applied

🐛 Defect 1: Screen Width & 36-Character Input Buffer Clamp Halting Lab 2.1 RESOLVED & VERIFIED

Symptom: When typing the compound statement in Lab 2.1 (FOR Y=0 TO 7:POKE 8192+Y*1024+20,255:NEXT Y), typing froze after column 36 and character 36 (past the comma). Characters could no longer be entered.

Root Cause: In index-standalone.html, typeChar(char) had a hardcoded clamp: if (this.currentInput.length >= 36) return;. Additionally, the line renderer did not wrap characters across multiple 40-column VRAM text rows.

Fix Applied: Expanded input buffer capacity to 239 characters (authentic Applesoft GETLN limit), implemented multi-row wrapping in renderCurrentInput(showCursor) across 40-column boundaries with scroll-up safety, fixed backspace() to clear vacated rows, and updated handleReturn() to advance cursor rows based on wrapped line count.

🐛 Defect 2: Immediate Mode Compound Statements & FOR...NEXT Loop Execution RESOLVED & VERIFIED

Symptom: Executing compound immediate commands like FOR Y=0 TO 7:POKE 8192+Y*1024+20,255:NEXT Y only executed the first iteration or failed to loop because immediate mode used simple JavaScript array iterations.

Root Cause: Immediate mode split commands by colons (cmd.split(':')) and iterated over them sequentially with forEach(), which broke all pointer-driven flow control statements (FOR...NEXT, GOTO).

Fix Applied: Implemented a dedicated immediate execution engine (this.executeImmediate(cmd)) that wraps immediate statements into a temporary frame ([{ lineNum: 0, statements: [...] }]) and executes them through the full BASIC stepping loop, executing all 8 loop iterations.

🐛 Defect 3: Uninitialized basicVars & basicForLoops in Direct Mode RESOLVED & VERIFIED

Symptom: Evaluating variables in direct immediate mode prior to executing a numbered program caused a JavaScript TypeError: Cannot set properties of undefined (setting 'Y').

Root Cause: this.basicVars and this.basicForLoops were only initialized when runBasic() was invoked for numbered programs.

Fix Applied: Explicitly initialized this.basicVars = {} and this.basicForLoops = {} in both the constructor() and reset() methods of Apple2cEmulator.

🐛 Defect 4: 32KB System ROM Reset & Subroutine Vector Offsets ($7800 vs $3800) RESOLVED & VERIFIED

Symptom: Inspecting reset vector opcodes at $F800 or calling HOME subroutine at $FC58 executed uninitialized zeros instead of clean-room BIOS routine opcodes.

Root Cause: The emulator ROM buffer is 32KB representing memory space $8000–$FFFF. Handlers were written to offsets 0x3800 ($B800) and 0x3c58 ($BC58) based on a 16KB ROM assumption, rather than 0x7800 ($F800) and 0x7c58 ($FC58).

Fix Applied: Corrected all ROM offset calculations in initSystemRom() to map addresses $F800–$FFFF directly to ROM buffer offsets 0x7800–0x7FFF.

🐛 Defect 5: CALL -151 Did Not Enter 65C02 Machine Language Monitor RESOLVED & VERIFIED

Symptom: When the user typed CALL -151 or CALL 65385, the emulator did nothing and remained in Applesoft BASIC without displaying the monitor prompt (* █).

Root Cause: The immediate statement dispatcher in index-standalone.html parsed high-level BASIC statements (HOME, PRINT, POKE) but lacked a branch to handle ROM monitor entry vectors and initiate the interactive machine language monitor loop.

Fix Applied: Added isMonitorMode state and executeMonitorCommand() in index-standalone.html. When CALL -151 is typed, the emulator switches prompt from ] █ to * █ and processes hex deposits (ADDR: BYTE BYTE...), execution (ADDR G), memory dumping (START.END), disassembly (ADDR L), and BASIC return (3D0G).

🐛 Defect 6: JSR $FDED (COUT) Character Output Vector Hook RESOLVED & VERIFIED

Symptom: Custom assembly routines that called the standard character output subroutine at $FDED (COUT) executed but did not render characters to the CRT screen or printer feed.

Root Cause: The synthetic ROM initialized memory at $FDED ($7DED) with a plain RTS opcode ($60) without intercepting CPU execution to pipe the Accumulator value into the active screen/printer output stream.

Fix Applied: Hooked instruction execution of $FDED in Apple2cEmulator.execute65C02() directly to this.typeChar(String.fromCharCode(this.cpu.a & 0x7F)), enabling seamless string printing in raw assembly programs.

🐛 Defect 7: Informational Status Text Injected onto Printer Paper & Trailing Sheets RESOLVED & VERIFIED

Symptom: Clicking the "Clear Buffer" button printed "[Printer buffer cleared]" onto the continuous paper feed, contaminating subsequent printouts, and PDF export created trailing blank pages.

Fix Applied: Refactored clearPrinterBuffer() to strictly reset the internal text buffer to an empty string ("") and reset the byte counter without appending informational strings. Added Pure Blank White and Ivory paper stock modes, and strict isolated @media print CSS styling for crisp 1-page PDF export.
