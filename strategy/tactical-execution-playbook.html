Phase 1: Hosting Deployment & Offline Desktop Packaging (First Steps)

How to host on apple2.ianohlander.com and package the offline desktop application

Step 1 of 5
1.1 Deploy Web Subdomain (apple2.ianohlander.com)
Time: ~5 mins | Cost: $0
Your Situation: You have ianohlander.com registered on GoDaddy, and a Hostinger VPS that is currently serving another active project.

🎯 Top Recommendation: GitHub Pages with GoDaddy CNAME (Zero VPS Risk)

Even though you have a Hostinger VPS, we strongly recommend deploying the public web emulator via GitHub Pages with a GoDaddy CNAME:

  • Protects Your VPS: Puts 0% CPU/RAM load on your Hostinger VPS. If a Hacker News post drives 100,000 visitors, your other VPS project will never experience crashes, slowdowns, or memory exhaustion.
  • Fastly Edge Global CDN: GitHub Pages caches the emulator across hundreds of worldwide edge data centers with sub-10ms latency.
  • Automated Updates: Every time you push code, GitHub automatically deploys the update.
Exact Click-by-Click Instructions for GoDaddy DNS:
  1. Log into your GoDaddy Account → My Products → ianohlander.com → Manage DNS.
  2. Click Add New Record.
  3. Type: Select CNAME.
  4. Name / Host: Enter apple2 (this creates the subdomain apple2.ianohlander.com).
  5. Value / Target: Enter ianohlander.github.io
  6. TTL: 1/2 Hour (or Default) → Click Save.
  7. In your GitHub repo (ianohlander/Apple-IIc-Enhanced-Emulator), go to Settings → Pages.
  8. Under Custom Domain, enter apple2.ianohlander.com → check Enforce HTTPS.
Alternative (Hostinger VPS Nginx Virtual Host):

If you prefer running on your Hostinger VPS alongside your other project, add an A Record in GoDaddy pointing apple2 to your VPS IP, and copy our pre-configured virtual host file (deploy/hostinger-nginx.conf) to /etc/nginx/sites-available/apple2.ianohlander.com. It isolates web roots safely without interfering with your existing project.

1.2 Package the Downloadable Offline Desktop Application
Time: ~15 mins | Fully Automated

🎯 Top Recommendation: Tauri 2.0 (Rust Backend + Web Frontend)

For downloadable offline applications, Tauri 2.0 is the industry gold standard over traditional Electron:

✅ Why Tauri Wins for Apple //c Ultra:
  • Tiny Installer Size: <10 MB installer (vs 150MB+ Electron bloat).
  • Anti-Tamper Source Protection: Embeds and encrypts web code directly inside compiled C/Rust binary machine code (.exe/.dmg), preventing easy app.asar extraction.
  • Decoupled User Storage: User disks and cards are cleanly saved to ~/Documents/Apple2Ultra/.
📦 Generated Binaries:
  • Windows: Standalone .exe and .msi installer.
  • macOS: .dmg installer and Universal binary (Apple Silicon + Intel).
  • Linux: .AppImage and .deb package.
Terminal Commands to Build (Zero Rust Experience Needed): 
# 1. Build frontend bundle
npm run build

# 2. Build native release binaries for your OS
npm run tauri build

The production installer files will be located in src-tauri/target/release/bundle/ ready to upload to your storefront!

Filing Form TX at eco.copyright.gov:

  2. Type of Work: Literary Work (Computer Software).
  3. Title: Apple //c Ultra Architecture, AOT Compilers, and Systems Engineering Courseware.
  4. Author: Ian Ohlander (Citizen: USA). Check boxes for Computer Program and Text.
  5. Limitation of Claim: Material Excluded = Standard 6502 instruction opcodes and ROM entry points; New Material = Original TypeScript/Rust emulation codebase, clean-room BIOS, C#/Java AOT compilers, and textbook.
