Understanding the Three-Domain Hardware Architecture

To understand how virtual expansion cards work in the 65C02 Ultra Workstation, we divide the entire system into Three Distinct Architectural Domains:

Domain 1: Inside
The 65C02 Virtual Computer

65C02 CPU executing Applesoft BASIC, 65C02 Machine Code, C# .NET, or Java 17. Reads/writes softswitches at $C0B0–$C0BF.

Domain 2: Middle
The Virtual Peripheral Card

JavaScript script in the Sandbox. Runs inside the host browser runtime with full access to Web APIs: Web Serial, Fetch, WebSockets, Web MIDI.

Domain 3: Outside
The Outside World

Physical Arduinos, ESP32s, stepper motors, servo actuators, cloud REST weather feeds, local Python/Node daemons, and MIDI synthesizers.

Slot Universality: Can Virtual Cards Be Plugged Into Any Slot?

Complete explanation of slot independence, address decoding formulas, and the 7-slot peripheral matrix

🔌 The Direct Answer: YES, Virtual Cards Are 100% Slot-Agnostic!

Custom JavaScript virtual cards can be assigned to ANY of the 7 slots (Slot 1 through Slot 7). There is no hardware restriction requiring custom cards to live in Slot 3.

The Workstation's SlotManager dynamically routes 65C02 CPU bus reads and writes according to standard 8-bit bus address decoding rules. When you plug a card into Slot n (where n ∈ [1..7]), the emulator automatically binds your card's onReadHandler and onWriteHandler to that slot's dedicated 16-byte I/O register range and 256-byte firmware ROM space.

🏛️ Why Slot 3 is Used as the Default Example:

On the vintage 1984 Apple //e and 6502 Ultra, Slot 3 was historically designated for the 80-Column Display Card (or Aux RAM), Slot 6 was the Disk II 5.25" floppy controller, and Slot 7 was the ProDOS SmartPort hard disk.

Our cookbook examples and tutorial presets default to Slot 3 so that beginners can experiment with custom IoT hardware immediately without disabling their floppy drive (Slot 6) or hard disk (Slot 7).

🚀 Ultra Reconfigurability: Replace Any Peripheral:

In the 6502 Ultra, all 7 slots are fully reconfigurable! You can hot-swap or replace any slot:

  • Slot 1: Replace ImageWriter Printer with a 32-Bit Math Co-Processor.
  • Slot 2: Replace MIDI/Serial with a Live Bitcoin Ticker or Weather Station.
  • Slot 4: Replace Thunderclock with an Arduino Stepper Motor Controller.
  • Slot 5: Replace Uthernet with an AI Neural Inference Accelerator.

Browser Security, Privacy Sandboxing & User Permission Model

How the browser protects users from unauthorized local device access or silent process execution

🔒 Core Security Guarantee: Zero Silent or Unauthorized Access

A common concern when running web-hosted emulators is: "Can a website secretly access my USB devices, scan my home network, or execute programs on my computer?"

The answer is NO, ABSOLUTELY NOT. Modern web browsers (Chrome, Edge, Firefox, Safari) enforce an impenetrable multi-layered security sandbox. A web-hosted application has zero ability to touch your local operating system or hardware without explicit user initiation and native OS permission dialogs.

How Permissions Work for Each Feature:

1. Physical USB Serial Ports (Web Serial API — Arduinos / ESP32s) Native Browser Prompt

How It Works: The browser will NEVER automatically connect to a USB device. The user must explicitly click a button (e.g. "Connect USB Port").

When clicked, the browser renders an unforgeable native security modal: "apple2.ianohlander.com wants to connect to a serial port" with a dropdown of plugged-in USB COM ports. The user must manually select their device (e.g. "Arduino Uno (COM3)") and click "Connect".

✓ Security Boundary: The website only receives access to that single approved port. It cannot scan the hard drive, read other USB ports, or access any other hardware.

2. Local Host Processes & Shell Commands (Local Daemon — Case Study 3) User-Run Bridge Only

Can a website execute local terminal commands on its own? Absolutely not. Web browsers completely prohibit web pages from spawning OS processes or executing binaries (calc.exe, shell scripts, etc.).

How Case Study 3 Actually Works: It is designed for advanced hobbyists who intentionally choose to run their own local companion daemon (e.g. a 10-line Python script or Electron sidecar) on localhost:8080. The web emulator merely sends WebSocket messages to the user's own local script.

✓ Security Boundary: If the user does not run the local Python daemon, the WebSocket simply refuses connection, and zero external interaction occurs.

3. Musical MIDI Keyboards & Synthesizers (Web MIDI API) Permission Modal

Modern browsers prompt the user with a permission banner: "Allow apple2.ianohlander.com to use your MIDI devices?". The user can block or allow access at any time.

4. Default Emulator Usage (Games, BASIC, C# AOT, Disks, Audio) 0 Permissions Needed

For 99% of normal emulator operations (playing games, writing BASIC, compiling C# and Java, editing disks, flashing custom ROMs, and listening to Mockingboard chiptunes), ZERO browser permissions are ever requested.

Why Users Can Trust the 6502 Ultra:
1. 100% Offline Single-File Option: The entire emulator is distributed as a single standalone HTML file (index-standalone.html) that users can save to their desktop and run completely offline with zero internet access!
2. Strictly Opt-In Permissions: No permission modals are ever triggered unless the user explicitly navigates to the Slot Studio and clicks "Connect USB Device".
3. Open-Source Transparency: All emulator source code, slot managers, and compilers are fully open, auditable, and contain zero tracking or telemetry beacons.
4. Native Desktop Wrapper Ready: For environments where browser prompts are undesirable, the emulator can be run inside a native Tauri / Electron desktop container.

Case Study 1: 6502 Ultra Driving an Outside Stepper Motor (Actuator Output)

How the 65C02 sends motor step commands through the JS card to a physical USB Arduino and motor

This example shows how a 6502 Ultra program writes a target step angle (e.g. 90 degrees) to softswitch register $C0B0, which the JavaScript card receives in card.onWriteHandler, transmits over USB serial, and causes a physical 28BYJ-48 stepper motor to rotate in the real world!

Domain 3: Outside World Arduino C++ Firmware (Uploaded to Physical Arduino Uno + ULN2003 Motor Board) 
// Flash this sketch to your Arduino connected to a 28BYJ-48 Stepper Motor
#include <Stepper.h>

const int STEPS_PER_REV = 2048; // 28BYJ-48 motor steps per full 360 deg turn
Stepper myMotor(STEPS_PER_REV, 8, 10, 9, 11);

void setup() {
  Serial.begin(9600); // 9600 Baud USB Serial
  myMotor.setSpeed(10); // 10 RPM
}

void loop() {
  // Listen for step command bytes sent from 6502 Ultra
  if (Serial.available() > 0) {
    byte targetAngle = Serial.read(); // Byte from 6502 Ultra (e.g. 90 deg)
    int stepsToMove = map(targetAngle, 0, 360, 0, STEPS_PER_REV);
    
    myMotor.step(stepsToMove); // Rotate physical motor shaft!
    
    // Send confirmation byte back to 6502 Ultra
    Serial.write(0x01); // 0x01 = Movement Complete
  }
}
Domain 2: Virtual Card Sandbox JavaScript Card Script (Paste in Slot & Card Studio → Slot 3 Sandbox) 
// Stepper Motor Controller Card (Slot 3 @ $C0B0)
card.serialPort = null;
card.serialWriter = null;
card.isMotorBusy = 0; // 0 = Ready, 1 = Moving

// Connect to USB Arduino Port
card.connectUsb = async () => {
  try {
    card.serialPort = await navigator.serial.requestPort();
    await card.serialPort.open({ baudRate: 9600 });
    
    card.serialWriter = card.serialPort.writable.getWriter();
    const reader = card.serialPort.readable.getReader();
    
    // Background reader listening for Arduino motor completion
    while (true) {
      const { value, done } = await reader.read();
      if (done) break;
      if (value && value.length > 0 && value[0] === 0x01) {
        card.isMotorBusy = 0; // Motor finished move!
        console.log("Motor rotation complete!");
      }
    }
  } catch (err) {
    console.warn("Serial Error:", err);
  }
};

// 65C02 Softswitch Read ($C0B0): Status register
card.onReadHandler = (offset) => {
  if (offset === 0x00) return card.isMotorBusy; // Returns 1 if busy, 0 if ready
  return 0x00;
};

// 65C02 Softswitch Write ($C0B0): Command register (angle 0-255)
card.onWriteHandler = async (offset, val) => {
  if (offset === 0x00 && card.serialWriter) {
    card.isMotorBusy = 1; // Mark motor busy
    await card.serialWriter.write(new Uint8Array([val])); // Send angle byte over USB!
  }
};

// Cloud Weather Station Card (Slot 3 @ $C0B0)
card.tempF = 74;
card.humidity = 52;
card.pressure = 1013;
card.windSpeed = 12;

// Fetch live weather from cloud API every 60 seconds
async function updateLiveWeather() {
  try {
    const res = await fetch("https://api.weather.gov/gridpoints/MTR/90,105/forecast");
    const data = await res.json();
    card.tempF = data.properties.periods[0].temperature;
    card.humidity = data.properties.periods[0].relativeHumidity.value || 50;
    card.windSpeed = parseInt(data.properties.periods[0].windSpeed) || 10;
  } catch (err) {
    console.warn("Weather fetch error, using sensor defaults", err);
  }
}

updateLiveWeather();
setInterval(updateLiveWeather, 60000);

// 65C02 Softswitch Read Handler ($C0B0–$C0BF)
card.onReadHandler = (offset) => {
  if (offset === 0x00) return card.tempF & 0xFF;        // $C0B0: Temp (deg F)
  if (offset === 0x01) return card.humidity & 0xFF;     // $C0B1: Humidity (%)
  if (offset === 0x02) return card.pressure & 0xFF;     // $C0B2: Pressure Low
  if (offset === 0x03) return (card.pressure >> 8) & 0xFF; // $C0B3: Pressure High
  if (offset === 0x04) return card.windSpeed & 0xFF;    // $C0B4: Wind Speed (mph)
  if (offset === 0x07) return 0x80;                    // $C0B7: Data Ready Strobe
  return 0x00;
};

⚖️ Legal & Trademark Architecture Analysis: Peripheral Naming & SDK Namespaces
1. Peripheral Card Trademarks (ImageWriter, Passport, Mockingboard):

Names like ImageWriter (Apple Computer Inc.), Mockingboard (Sweet Micro Systems), and Passport (Passport Designs) were historical commercial trademarks. Distributing virtual expansion cards under these exact proprietary brand names as standalone products could open an author to trademark infringement or false designation of origin claims under Lanham Act §43(a).

The Solution: We adopt generic, descriptive functional titles (e.g. Vintage 8-Pin Dot Matrix Printer Card, Dual 6-Channel Sound Synthesizer) and state compatibility strictly through nominative fair use (e.g. "ImageWriter II Protocol Compatible").

2. C# & Java Package Namespaces (`Apple2` vs `A2Ultra`):

Publishing a public SDK or library package using proprietary names like Apple2.Ultra or package apple2.hardware presents trademark liability because it creates commercial confusion implying official endorsement by Apple Inc.

The Solution: The official Workstation SDK uses A2Ultra.Hardware (C#) and package a2ultra.hardware (Java). Legacy projects referencing Apple2.Ultra are supported via backward-compatible internal type aliases.

💾 7. Disk II 5.25" Floppy & Dual Drive Controller Card (Slot 6 @ $C0E0 • Drive 1 & Drive 2)
Disk II $C600

Authentic Wozniak floppy controller supporting Dual 140KB 5.25" Floppy Drives (Drive 1 & Drive 2) simultaneously on a single controller card, using 6-and-2 GCR encoding and 4-phase stepper motor logic.

⚙️ How the Dual-Drive Hardware Works ($C0EA vs $C0EB):

The Disk II controller card in Slot 6 connects to two physical drive daisy-chains via a single 20-pin ribbon header. Both drives share the 4-phase stepper motor coils ($C0E0–$C0E7) and the read/write amplifier strobe ($C0EC–$C0EF). The 65C02 selects which physical drive mechanism is active via dedicated softswitches:

Drive 1 Select: $C0EA (Decimal 49386)
Activates Drive 1 motor and connects Drive 1 read head.
Drive 2 Select: $C0EB (Decimal 49387)
Activates Drive 2 motor and connects Drive 2 read head.
DOS 3.3 Dual-Drive Usage: 
] CATALOG, D1     : REM Catalog Drive 1
] CATALOG, D2     : REM Catalog Drive 2
] RUN GAME, D1    : REM Launch game from D1
] SAVE SCORES, D2 : REM Save scores to D2
] COPY S6,D1 TO S6,D2 : REM Duplicate disk
ProDOS Volume & Drive Usage: 
] CAT, S6, D1     : REM Catalog Drive 1
] CAT, S6, D2     : REM Catalog Drive 2
] PREFIX /DATA.DISK : REM Set path to D2
] -SYSTEM.LOADER  : REM Run ProDOS binary
] -/DATA.DISK/DATA.FILE : REM Access D2
💡 How to Mount and Use Both Drives Simultaneously in the Emulator:
  1. Open the Floppy & 32MB Storage Bay tab.
  2. Under Disk II Floppy Drive 1, choose your boot disk image (e.g. ProDOS 2.4.2 System Disk or DOS 3.3 Master).
  3. Under Disk II Floppy Drive 2, choose your secondary disk image (e.g. ProDOS Utilities Disk or a blank data disk).
  4. Click ⚡ Boot Drive 1. When the software prompts to access data from Drive 2, it reads from Drive 2 without needing to swap disks!
⚡ 8. SmartPort 32MB Hard Disk Controller (Slot 7 @ $C0F0 • ProDOS MLI)
ProDOS $C700

65,536-block contiguous mass storage controller (/HD). Provides instantaneous block I/O via ProDOS Machine Language Interface (MLI) driver vectors at $C700. Includes the 1-click ProDOS disk exporter (.DSK / .PO / .2MG) for physical deployment to CFFA3000 cards.

ProDOS SmartPort MLI Call: 
; Read Block 2 from Slot 7 Unit $70 (/HD)
LDA #$01        ; MLI Command: READ_BLOCK
STA $0800
LDA #$70        ; Unit $70 = Slot 7, Drive 1
STA $0801
LDA #$02        ; Block Low = 2
STA $0802
LDA #$00        ; Block High = 0
STA $0803
LDA #$00        ; Buffer Pointer Low ($2000)
STA $0804
LDA #$20        ; Buffer Pointer High ($2000)
STA $0805
JSR $C700       ; Call SmartPort Driver
