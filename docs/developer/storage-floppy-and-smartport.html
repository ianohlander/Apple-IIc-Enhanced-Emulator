The Apple //c Ultra features a unified, multi-tier storage architecture bridging vintage physical media with high-capacity mass storage: from Steve Wozniak's revolutionary 6-and-2 Group Code Recording (GCR) 5.25" floppy controller, through the Apple SmartPort 32MB virtual hard disk partition protocol ($65,536$ contiguous 512-byte blocks), to the ultra-fast Slinky 1MB Auxiliary RAM Disk and managed object-oriented file persistence in C# .NET and Java 17.

1. Wozniak 6-and-2 Group Code Recording (GCR) & Disk II Mechanics

Standard magnetic floppy drives record data as magnetic flux reversals. When more than two consecutive zero bits occur on the spinning oxide surface, the read head amplifier loses its self-clocking synchronization pulse, resulting in a bit-slip error. While rival systems (such as the Commodore 1541 or IBM PC) relied on complex, expensive hardware phase-locked loops (PLLs) and Western Digital controller chips, Steve Wozniak solved this entirely in software and simple TTL logic using 6-and-2 Group Code Recording (GCR).

📐 The Mathematical Nibblization Algorithm (256 Bytes $ o$ 342 Disk Bytes)

Ratio: 1 user byte = 1.3359 disk bytes

Because 6 bits can represent (2^6 = 64) discrete values, Wozniak created a 64-entry lookup table mapping every 6-bit nybble into an 8-bit disk byte whose most significant bit is always 1 and has no more than one pair of consecutive zeros:

1. Buffer Splitting (256 User Bytes)

- Primary Array: 256 bytes holding the upper 6 bits ((b_7 b_6 b_5 b_4 b_3 b_2)) of each byte.
- Secondary Array: 86 bytes holding the lower 2 bits ((b_1 b_0)) of three distinct bytes packed into a single 6-bit value ((86 imes 3 = 258 ge 256)).

2. 64-Entry GCR Translation Table

Every 6-bit index ($00..$3F) is translated to a valid 8-bit GCR byte ($96..$FF). When reading, a reverse lookup table of 256 bytes decodes valid GCR bytes back to 6-bit values ($00..$3F).

Physical Sector Format: Address Field & Data Field Anatomy

On physical media, each of the 16 sectors per track consists of an Address Field (which identifies the volume, track, sector, and checksum using 4-and-4 odd-even encoding) followed by a Data Field (which holds the 342 GCR-encoded user data bytes):

Field Component Byte Sequence Purpose / Significance
Address Prologue $D5 $AA $96 Unique 3-byte synchronization marker signaling the start of a sector header.
Address Payload 8 bytes (4-and-4) Volume, Track Number ($00..$22), Sector Number ($00..$0F), and Header Checksum.
Address Epilogue $DE $AA $EB Confirms valid header framing and read-head alignment.
Data Prologue $D5 $AA $AD Unique 3-byte synchronization marker signaling the start of user sector data.
Data Payload 342 GCR bytes 86 bytes secondary array + 256 bytes primary array XOR-checksummed on the fly.
Data Checksum 1 GCR byte Cumulative XOR value across all 342 nibbles to verify zero transmission errors.
Data Epilogue $DE $AA $EB Trailing framing bytes verifying end-of-sector data capture.

4-Phase Stepper Motor Head Positioning Logic ($C0EC..$C0EF)

The read/write head is actuated by a 4-phase unipolar stepper motor. The Apple //c motherboard addresses the motor phases via softswitches located at $C0E0..$C0E7 (or Slot 6 standard $C0EC..$C0EF):

PHASE 0 $C0E0 OFF / $C0E1 ON Track 0, 4, 8, 12, ...
PHASE 1 $C0E2 OFF / $C0E3 ON Track 1, 5, 9, 13, ...
PHASE 2 $C0E4 OFF / $C0E5 ON Track 2, 6, 10, 14, ...
PHASE 3 $C0E6 OFF / $C0E7 ON Track 3, 7, 11, 15, ...

To step inward by one full track: Energize next phase $ o$ wait 2.5ms settle delay $ o$ de-energize previous phase. Quarter and half-stepping can be achieved by energizing adjacent phases simultaneously.

Sector Interleaving: DOS 3.3 Skew vs. ProDOS 512-Byte Block Mapping

Because the 65C02 CPU requires processing cycles between reading adjacent sectors, sectors are interleaved (skewed) on the track surface to maximize rotational throughput:

DOS 3.3 Physical-to-Logical Skew Table

Physical sectors $00..$0F map to DOS 3.3 logical sectors in the order:
[0, 7, 14, 6, 13, 5, 12, 4, 11, 3, 10, 2, 9, 1, 8, 15]

ProDOS 512-Byte Block Skew Table (2 Sectors/Block)

ProDOS groups two 256-byte sectors into one 512-byte block with interleaved physical pairs:
[0, 8, 1, 9, 2, 10, 3, 11, 4, 12, 5, 13, 6, 14, 7, 15]

2. SmartPort 32MB Virtual Hard Disk & ProDOS File Allocation

The Apple //c Ultra implements the extended Apple SmartPort firmware interface connected to a massive 32 Megabyte virtual hard disk volume (/HD) in Slot 7. The volume contains 65,536 contiguous 512-byte logical blocks ($65,536 imes 512 = 33,554,432 ext{ bytes}$).

🗂️ ProDOS 32MB Hard Disk Block Map Layout

ProDOS File Storage Topologies: Seedling, Sapling & Tree Files

ProDOS automatically selects one of three physical allocation topologies based on file length:

🌱 Seedling File ($le 512$ Bytes)

Takes exactly 1 block. The directory entry's KEY_POINTER points directly to the data block itself.

🌿 Sapling File ($513 ext{B} .. 128 ext{KB}$)

Uses 1 Index Block containing up to 256 two-byte block pointers ($256 imes 512 ext{B} = 128 ext{KB}$). The directory key pointer references the index block.

🌳 Tree File ($128 ext{KB} .. 16 ext{MB}$)

Uses a Master Index Block holding up to 128 index block pointers. Each sub-index block points to 256 data blocks, enabling files up to 16MB.

ProDOS Machine Language Interface (MLI) Specification

Applications invoke ProDOS storage functions via direct driver calls at JSR $C700 (or global system call JSR $BF00):

Low-Level Block Driver ($C700 / $C600) 
; Direct Block I/O Calling Convention
; Accumulator = Unit Number ($70 = S7,D1; $60 = S6,D1)
; X-Reg = Parameter List Pointer Low ($00-$FF)
; Y-Reg = Parameter List Pointer High ($00-$FF)
; Carry Flag: Clear = Success, Set = Error

LDA #$70        ; Unit: Slot 7, Drive 1
LDX #PARAM_BLK ; Pointer High
JSR $C700       ; Call SmartPort Block Driver
BCS I_O_ERROR   ; Branch if Carry set (Error in A)
MLI Command Parameter Block Structure 
PARAM_BLK:
  .BYTE $03     ; Parameter Count (3)
  .BYTE $70     ; Unit Number (Slot 7, Drive 1)
  .WORD $2000   ; 512-Byte Data Buffer Pointer in RAM
  .WORD $0002   ; 16-Bit Block Number (e.g. Block 2)

; MLI Error Return Codes (Returned in Accumulator):
; $00 = No Error (Success)
; $27 = I/O Error (Read/Write Failure)
; $28 = No Device Connected
; $2B = Disk Write-Protected
; $40 = Invalid Pathname Syntax
; $46 = File Not Found
; $4E = File Access / Permission Error

3. Slinky 1MB Auxiliary RAM Disk Architecture

The Apple //c Ultra incorporates the famous Apple //c Memory Expansion Card ("Slinky") providing 1,048,576 bytes of fast banked memory. The hardware operates through 24-bit auto-incrementing address registers mapped at $C0C8..$C0CB:

$C0C8 (Addr LSB) Bits $A_0..A_7$
$C0C9 (Addr MID) Bits $A_8..A_{15}$
$C0CA (Addr MSB) Bits $A_{16}..A_{19}$
$C0CB (Data Port) Auto-Increment R/W
High-Speed Zero-Cycle DMA Paging Loop in 65C02 Assembly: 
; Stream 512 bytes from Slinky RAM Disk into Main RAM $4000
  LDA #$00 : STA $C0C8       ; Address Low = $00
  LDA #$02 : STA $C0C9       ; Address Mid = $02 (Offset $0200 = 512 bytes)
  LDA #$00 : STA $C0CA       ; Address High = Bank 0
  LDY #$00
PAGE_LOOP:
  LDA $C0CB                  ; Read byte from Slinky (Hardware auto-increments address!)
  STA $4000,Y                ; Store in target RAM
  LDA $C0CB                  ; Read next byte
  STA $4100,Y                ; Store in next 256-byte page
  INY
  BNE PAGE_LOOP              ; Fast 256-iteration loop transfers all 512 bytes

4. Modern Managed Storage APIs (C# .NET & Java 17) & AOT Lowering

Modern object-oriented programs compiled through the Apple //c Ultra AOT compiler can persist state and stream assets seamlessly using standard high-level file APIs and hardware block drivers:

C# .NET Standard Storage Interface 
using System.IO;
using Apple2.Ultra;

public class GameStateManager {
    public static void SaveHighScores(int score) {
        // High-Level Text Persistence
        File.WriteAllText("/HD/HISCORES.DAT", "SCORE:" + score);

        // Low-Level Direct Block Persistence (Slot 7 Block 100)
        byte[] buffer = new byte[512];
        buffer[0] = (byte)(score & 0xFF);
        buffer[1] = (byte)((score >> 8) & 0xFF);
        AppleStorage.WriteBlock(AppleStorage.UnitSlot7Drive1, 100, buffer);
    }
}
Java 17 Standard Storage Interface 
import java.io.File;
import apple2.hardware.AppleStorage;

public class TelemetryLogger {
    public static void recordSample(int temp, int pressure) {
        // High-Level File Persistence
        File file = new File("/HD/LOG.TXT");
        file.writeText("TEMP=" + temp + ",PRESS=" + pressure);

        // Low-Level Block Stream (Slot 7 Block 200)
        byte[] block = new byte[512];
        block[0] = (byte)temp;
        block[1] = (byte)pressure;
        AppleStorage.writeBlock(AppleStorage.UNIT_SLOT7_DRIVE1, 200, block);
    }
}
