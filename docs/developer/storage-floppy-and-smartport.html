IWM (Integrated Woz Machine) 6-and-2 GCR nibblizing state sequencer alongside SmartPort 32MB ProDOS block transaction driver:

1. Wozniak 6-and-2 Group Code Recording (GCR)

Standard 5.25-inch floppy drives use magnetic flux transitions to represent binary ones and zeros. If more than two consecutive zero bits occur on the physical media, the drive read-head loses clock synchronization, causing a "bit-slip" error. Steve Wozniak solved this by designing the 6-and-2 GCR encoding scheme:

Nibblization: Converting 256 User Bytes into 342 Disk Bytes

  1. A 256-byte sector is split into two arrays: a 256-byte primary array holding the upper 6 bits of each byte, and an 86-byte secondary array holding the lower 2 bits of three distinct bytes packed together (\(86 \times 3 = 258 \ge 256\)).
  2. Each 6-bit value is translated through a 64-entry lookup table into an 8-bit GCR disk byte where the most significant bit (bit 7) is always 1 and no more than two adjacent zeros exist.
  3. Before each sector data field, the controller writes a unique 3-byte synchronization header: $D5 $AA $96 (for address field) and $D5 $AA $AD (for data field).

2. 4-Phase Stepper Motor Head Positioning Logic

The 5.25-inch floppy read/write head is positioned using a 4-phase stepper motor controlled by softswitches $C0E0..$C0E7. Energizing Phase 0, 1, 2, or 3 moves the head inward or outward by 1/2 track increments. Full-tracking requires cycling through phases in sequence: \(\text{Phase 0} \to \text{Phase 1} \to \text{Phase 2} \to \text{Phase 3}\).

3. SmartPort 32MB Hard Disk Block I/O Engine

The Apple //c Ultra implements the Apple SmartPort firmware protocol configured with an extended 32 Megabyte virtual hard disk ($/HD$). The storage volume is partitioned into 65,536 contiguous 512-byte blocks. ProDOS 2.4.2 communicates directly with the driver using standard block read/write commands: 

// SmartPort Block Transfer Packet Layout
struct SmartPortPacket {
    byte command;       // 0x01 = Status, 0x02 = Read Block, 0x03 = Write Block, 0x04 = Format
    byte unitNumber;    // 0x01 = First SmartPort Device ($/HD)
    word bufferPointer; // Pointer in RAM to 512-byte payload buffer
    word blockNumber;   // 16-bit Block Number (0..65535)
};

MANAGED APIS

Modern Language Storage APIs (C# .NET & Java 17)

Modern C# and Java applications running on the 65C02 silicon can access the 32MB SmartPort hard disk directly via high-level file APIs and block drivers:

C# .NET Core Storage Access 
using System.IO;
using Apple2.Ultra;

// 1. High-Level File Persistence
File.WriteAllText("/HD/SCORES.TXT", "PLAYER: WOZ 9999");
string log = File.ReadAllText("/HD/SCORES.TXT");

// 2. Low-Level ProDOS MLI Block Driver ($C700)
byte[] blockData = new byte[512];
AppleStorage.WriteBlock(AppleStorage.UnitSlot7Drive1, 2, blockData);
byte[] readBack = AppleStorage.ReadBlock(AppleStorage.UnitSlot7Drive1, 2);
Java 17 Storage Access 
import java.io.*;
import apple2.hardware.*;

// 1. High-Level File Streams
File file = new File("/HD/CONFIG.DAT");
FileOutputStream out = new FileOutputStream(file);
out.write(new byte[]{0x01, 0x02, 0x03});

// 2. ProDOS MLI Block Driver ($C700)
byte[] buffer = new byte[512];
AppleStorage.writeBlock(AppleStorage.UNIT_SLOT7_DRIVE1, 2, buffer);
AppleStorage.readBlock(AppleStorage.UNIT_SLOT7_DRIVE1, 2, buffer);
