How Java & C# Execute on the 65C02 CPU

A deep architectural exploration of modern Object-Oriented bytecode translation, Zero Page register virtualization, memory layout, and the Apple II hardware API bindings.

1. The Lineage: Sweet16, UCSD Pascal & Virtual Machines

Running higher-level virtual machine bytecodes on an 8-bit Apple II is not a foreign concept; it is part of Apple's deepest DNA:

Sweet16 (Steve Wozniak, 1977)

Woz created Sweet16, a 16-bit virtual processor implemented as a 6502 bytecode interpreter in the Apple II Integer BASIC ROM. It mapped 16 virtual 16-bit registers (R0–R15) into Zero Page ($00–$1F), enabling 16-bit pointer arithmetic and memory addressing in compact code.

UCSD Pascal p-System (1979)

The Apple II Pascal system compiled structured Pascal source code into intermediate p-code, which was interpreted by a native 6502 p-machine runtime. It brought structured programming and separate compilation units to 64KB machines.

The Apple //c Ultra takes this heritage to its ultimate conclusion: using modern Ahead-Of-Time (AOT) compiler theory to take modern Java and C# source trees, parse their Abstract Syntax Trees (AST), and compile them directly down to native, un-emulated CMOS 65C02 machine instructions that run at up to 50 MHz Turbo clock rates!

2. The 65C02 AOT Compilation Pipeline

The compilation process operates through three distinct compilation stages:

Stage 1: Lexical Analysis & Statement Dispatch
Source lines are tokenized, isolating class definitions, methods, hardware API calls (AppleGraphics, AppleAudio, AppleSystem), loops, and arithmetic assignments.
Stage 2: Zero Page Virtual Register Allocation
High-level variables and evaluation stacks are mapped into dedicated fast Zero Page memory locations ($80–$EF), while the hardware stack ($0100–$01FF) is reserved for function frames and subroutine calls (JSR / RTS).
Stage 3: 65C02 Instruction Generation & Vector Linking
Emits optimized 65C02 instructions (including CMOS extensions like BRA, STZ, PHX/PLX, PHY/PLY), creates the program header at $2000, and initializes softswitch states.

3. Standard Hardware API Library Specification

Class: AppleGraphics (Java) / AppleVideo (C#)

Method Generated 65C02 Sequence Description
setVideoMode(MODE_DOUBLE_HIRES) STA $C050, STA $C057, STA $C00D, STA $C05F Engages 560×192 16-color Double Hi-Res mode.
clearScreen(color) LDA #col, LDY #$00, STA $2000,Y... Fills video memory $2000–$3FFF with color byte.

Class: AppleAudio (Java) / AppleSound (C#)

Method Generated 65C02 Sequence Description
beep(freq, duration) BEEP: LDA $C030, DLY: DEY, BNE DLY... Toggles 1-bit speaker cone at calibrated frequency.
playMockingboard(voice, freq, vol) STA $C0C0, STA $C0C1 (VIA in Slot 4) Programs AY-3-8910 tone generator voices 1–6.

Class: AppleSystem (Java) / Console (C#)

Method Generated 65C02 Sequence Description
print(string) / WriteLine(string) LDA #char | 0x80, JSR $FDED (COUT) Outputs characters through Apple IIc ROM terminal.
poke(address, value) LDA #val, STA addr Direct memory write to MMU bus.

import apple2.hardware.AppleGraphics;
import apple2.hardware.AppleAudio;
import apple2.hardware.AppleSystem;

public class UltraArcadeIntro {
    public static void main(String[] args) {
        // Step 1: Engage 560x192 Double Hi-Res Color Display
        AppleGraphics.setVideoMode(AppleGraphics.MODE_DOUBLE_HIRES);
        AppleGraphics.clearScreen(AppleGraphics.COLOR_BLACK);
        
        // Step 2: Play Dual Mockingboard & 1-Bit Speaker Fanfare
        AppleAudio.beep(523, 100); // C5
        AppleAudio.beep(659, 100); // E5
        AppleAudio.beep(783, 150); // G5
        AppleAudio.beep(1046, 250); // C6
        
        // Step 3: Print Welcome Message to Apple //c Screen
        AppleSystem.print("APPLE //C ULTRA - JAVA RUNTIME READY");
    }
}
