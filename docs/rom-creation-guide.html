Section 1: 32KB Physical ROM Architecture ($C000–$FFFF)

27C256 EPROM memory mapping, language card banking, and address decoding

On the Apple //c motherboard, the System ROM is housed in a 28-pin 32KB 27C256 EPROM (or 64KB 27C512 EPROM on Revision 3/4 machines). The upper 16KB of physical address space ($C000–$FFFF) is multiplexed across multiple internal sub-blocks:

Physical Address ROM File Offset Subsystem / Routine Description & Function
$C000–$C0FF N/A (Hardware I/O) Memory-Mapped Softswitches Keyboard, Speaker ($C030), Video, and MMU multiplexer softswitches.
$C100–$C7FF $0100–$07FF Slot ROM Extensions (Slots 1–7) Internal firmware drivers: Serial Port 1 ($C100), Serial Port 2 ($C200), 80-Col Firmware ($C300), Mouse ($C400), SmartPort HD ($C500), Disk II ($C600).
$C800–$CFFF $0800–$0FFF Shared Expansion ROM Shared banking space for auxiliary slot device subroutines.
$D000–$F7FF $1000–$37FF Applesoft BASIC Interpreter Floating-point math engine, syntax tokenizer, and interpreter loops.
$F800–$FFFA $3800–$3FFA System Monitor & Drivers Cold boot reset ($F800), HOME ($FC58), COUT ($FDED), KEYIN ($FD1B), and mini-assembler.
$FFFA–$FFFF $3FFA–$3FFF 65C02 Hardware Vector Table NMI ($FFFA), Cold Reset ($FFFC), and IRQ/BRK ($FFFE) entry vectors.

Section 2: 65C02 Hardware Interrupt Vector Table ($FFFA–$FFFF)

Linking NMI, Cold Reset, and IRQ/BRK vectors in Little-Endian machine format

The 65C02 microprocessor relies entirely on the final 6 bytes of the 64KB memory map ($FFFA–$FFFF) to direct execution upon power-up or hardware interrupt triggers. All addresses are stored in Little-Endian byte order (Low Byte followed by High Byte):

Vector Table Assembly Definition (.ORG $FFFA): 
.ORG $FFFA
        .WORD NMI_HANDLER   ; $FFFA-$FFFB: Non-Maskable Interrupt (e.g. Keyboard Reset / Debugger)
        .WORD RESET_HANDLER ; $FFFC-$FFFD: Cold Reset Vector (Power-Up / Hardware Reset)
        .WORD IRQ_HANDLER   ; $FFFE-$FFFF: Maskable Interrupt (VIA 6522, Mockingboard, BRK opcode)

Section 3: Anatomy of a Production Cold Boot Initialization Handler

Step-by-step assembly initialization of CPU registers, stack, MMU, and Video VRAM

When constructing custom firmware, your Cold Boot routine must initialize the machine from an undefined power-on silicon state: 

; =====================================================================
; APPLE //c ULTRA CUSTOM FIRMWARE COLD BOOT HANDLER ($F800)
; =====================================================================
        .ORG $F800

COLD_BOOT:
        SEI                 ; 1. Disable maskable IRQ interrupts
        CLD                 ; 2. Clear decimal mode flag (ensure binary ALU math)
        LDX #$FF
        TXS                 ; 3. Initialize Stack Pointer to top of Page 1 ($01FF)

        ; 4. Initialize MMU Memory Banking to Main 64KB RAM Bank
        STA $C000           ; 80STOREOFF: Normal video page mapping
        STA $C008           ; ALTZPOFF: Main Zero Page ($0000-$00FF) & Stack
        STA $C002           ; RAMRDOFF: Read from Main 64K RAM
        STA $C004           ; RAMWRTOFF: Write to Main 64K RAM

        ; 5. Initialize Video Display Controller to 40-Column Fullscreen Text
        STA $C051           ; TXTSET: Text Mode
        STA $C054           ; PAGE1: Display Video Page 1 ($0400-$07FF)
        STA $C052           ; MIXCLR: Full 24-Row Display (No split graphics)

        ; 6. Clear Video RAM Text Page 1 ($0400-$07FF) to High-Bit Blank Spaces ($A0)
        JSR CLEAR_SCREEN

        ; 7. Write Custom Firmware Power-On Banner to Row 0
        LDY #0
PRINT_BANNER:
        LDA BANNER_TEXT,Y
        BEQ START_KERNEL
        ORA #$80            ; Convert ASCII to Apple II High-Bit ASCII
        STA $0400 + 10,Y    ; Write to Row 0 Center VRAM ($0400)
        INY
        BNE PRINT_BANNER

START_KERNEL:
        ; 8. Speaker Power-On Chime ($C030)
        JSR PLAY_POWER_CHIME

        ; 9. Enter Kernel Command Loop
        JMP KERNEL_LOOP

CLEAR_SCREEN:
        LDY #0
        LDA #$A0            ; High-bit space ($A0)
CLR_LOOP:
        STA $0400,Y
        STA $0480,Y
        STA $0500,Y
        STA $0580,Y
        STA $0600,Y
        STA $0680,Y
        STA $0700,Y
        STA $0780,Y
        INY
        BNE CLR_LOOP
        RTS

PLAY_POWER_CHIME:
        LDX #100
CHIME_LOOP:
        STA $C030           ; Pulse speaker cone
        LDY #50
CHIME_WAIT:
        DEY
        BNE CHIME_WAIT
        DEX
        BNE CHIME_LOOP
        RTS

BANNER_TEXT:
        .ASCII "APPLE //c ULTRA CUSTOM ROM v1.0"
        .BYTE 0

Section 4: Designing Custom Character Generator ROMs (7x8 Font Matrix)

Pixel encoding, bitfield fonts, custom game tiles, and international character sets

The Apple //c Character Generator ROM stores a 7x8 dot matrix for 128 standard ASCII glyphs ($00–$7F). Each character requires 8 consecutive bytes, where each byte represents one horizontal row of 7 dots:

Example: Custom Space Invader Sprite Glyph (8 Bytes): 
Row 0:  . X . . . X .  -> $24  (0010 0100)
Row 1:  . . X . X . .  -> $14  (0001 0100)
Row 2:  . X X X X X .  -> $3E  (0011 1110)
Row 3:  X X . X . X X  -> $5B  (0101 1011)
Row 4:  X X X X X X X  -> $7F  (0111 1111)
Row 5:  X . X X X . X  -> $49  (0100 1001)
Row 6:  X . X . X . X  -> $49  (0100 1001)
Row 7:  . . X . X . .  -> $14  (0001 0100)

Section 5: Modern Toolchain, Assembly & Flashing Pipeline

Assembling with ca65 / vasm, linking 32KB binaries, and flashing EPROMs

To build and test custom ROMs on real hardware or inside the emulator:

1. Assemble with ca65: 
ca65 --cpu 65C02 -o custom_rom.o custom_rom.asm
ld65 -C apple2c_rom.cfg -o custom_rom.bin custom_rom.o
2. Inject into Apple //c Web Workstation via JavaScript API: 
// Load 32KB binary array directly into emulator ROM memory:
window.emulator.rom.set(customRomUint8Array, 0x0000);
window.emulator.reset();
