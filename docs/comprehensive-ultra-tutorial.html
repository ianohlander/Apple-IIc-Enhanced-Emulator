The Apple //c Architecture: 1984 Silicon vs. Ultra Enhancements

Understanding the core hardware model, memory maps, and homebrew accelerators

The 1984 Original Baseline

Released in April 1984, the original Apple //c (A2S4000) was Apple's first portable, closed-architecture computer. It was engineered around the WDC 65C02 CMOS CPU running at exactly 1.023 MHz. It shipped with 128 KB of RAM split evenly into two 64KB banks:

Main 64KB RAM Bank
  • $0000–$00FF: Main Zero Page (CPU direct addressing)
  • $0100–$01FF: Hardware Stack ($01FF down to $0100)
  • $0400–$07FF: Text & Lo-Res Graphics Primary Page
  • $0801–$95FF: Applesoft BASIC Program Memory
  • $2000–$3FFF: Primary Hi-Res Graphics Screen
  • $D000–$FFFF: Banked Language Card (RAM/ROM)
Auxiliary 64KB RAM Bank
  • $0000–$00FF: Aux Zero Page (via ALTZP $C009)
  • $0100–$01FF: Aux Stack
  • $0400–$07FF: 80-Column Text Odd Columns
  • $2000–$3FFF: Double Hi-Res Aux Byte Interleave
  • $D000–$FFFF: Aux Language Card Extended Storage

The "Ultra" Homebrew Enhancements

The Apple //c Ultra preserves 100% cycle-accurate compatibility with vintage software while expanding the machine with modern homebrew modifications:

⚡ 50 MHz Turbo Boost

Accelerates execution up to 50× vintage speed, selectable dynamically from 1.0 to 50.0 MHz.

💾 1MB Slinky RAM

24-bit auto-incrementing data port ($C071–$C073) providing 1,024 KB of banked memory.

💽 32MB SmartPort HD

65,536 blocks of 512 bytes with direct block I/O dispatch ($C0B0–$C0BF).

🎵 Mockingboard PSG

Dual AY-3-8910 programmable sound chips with 6 tone channels & white noise generators.

The Video & Graphics Pipeline

Understanding address interleaving, Hi-Res color shifts, Double Hi-Res, and mixed graphics modes

Why Apple II Video Memory is Interleaved

Unlike modern linear framebuffers, Steve Wozniak engineered the Apple II video generator to share DRAM refresh circuitry with the 6502 CPU. Because of this, scanline addresses are calculated using a 3-tier box interleaving formula:

$$\text{Base}(Y) = \$2000 + 1024 \times (Y \bmod 8) + 128 \times (\lfloor Y / 64 \rfloor) + 40 \times (\lfloor (Y \bmod 64) / 8 \rfloor)$$

Hi-Res Graphics (280 × 192, 6 Colors)

In HGR mode, each byte controls 7 pixels (bits 0–6). Bit 7 does not define a pixel—it shifts the subcarrier color clock by half a cycle ($180^\circ$), switching the available color palette:

Bit 7 = 0 Green / Purple
Bit 7 = 1 Orange / Blue
All 0s Black
All 1s White

Mixed Graphics Mode (Top Graphics + Bottom 4 Text Lines)

When executing HGR, the screen switches to mixed mode: the top 160 scanlines display Hi-Res graphics ($Y=0\dots159$), while the bottom 32 scanlines ($Y=160\dots191$) display 4 rows of text (rows 20–23, accessed via VTAB 21 through VTAB 24). Full-screen graphics is activated via HGR2 or POKE -16302, 0.

Sound Creation: 1-Bit Speaker to 6-Channel Mockingboard

Mastering 1-bit cycle timing, AY-3-8910 tone divisors, noise synthesis, and arcade SFX sound design

1. The Vintage 1-Bit Speaker ($C030 / 49200)

The original Apple II had no dedicated sound chip. Reading or writing address $C030 (49200) toggles a hardware flip-flop connected to a small speaker cone, generating a single click. By toggling $C030 inside a tight cycle-counted delay loop, square wave frequencies are produced: 

; 65C02 Routine: Play 880 Hz Beep
BEEP:   LDY #$80        ; Duration count
LOOP1:  LDA $C030       ; Toggle speaker
        LDX #$72        ; Pitch delay period (~568 microseconds)
LOOP2:  DEX
        BNE LOOP2
        DEY
        BNE LOOP1
        RTS

2. The Dual AY-3-8910 Mockingboard PSG Architecture

The Apple //c Ultra integrates dual General Instrument AY-3-8910 Programmable Sound Generators (PSGs) controlled via 6522 VIAs. Each chip provides 3 independent square-wave channels (total 6 channels across stereo L/R):

12-Bit Tone Generator

Calculates tone frequency via 12-bit period divisor $R0–R5$:

$$f = \frac{1\,000\,000}{16 \times \text{Period}}$$
5-Bit Noise Generator

Linear-feedback shift register ($R6$) generating white noise for explosions, snares, and laser hits.

16-Bit Envelope Modulator

$R11–R13$ hardware attack, decay, sustain, and cyclic triangle/sawtooth amplitude shapes.

Sound Effect (SFX) Design Recipes

Laser Cannon Blast

Sweep period divisor from $0020 (high pitch) down to $0200 (low pitch) in a rapid decrement loop while enabling white noise on Channel A.

Explosion Rumble

Set Noise Period $R6 = $1F (deep rumble), Mixer $R7 = $37 (noise only on Channel A), and Envelope Shape $R13 = $00 (single decay fade).

Custom ROM & Firmware Creation

Mastering 65C02 vector tables, custom bootloaders, and firmware patching

The 32KB System ROM Structure ($D000–$FFFF)

The Apple //c ROM image occupies the upper 32KB of the address space and consists of three critical sub-modules:

$C100–$C7FF: Slot ROMs

Built-in firmware for Serial 1/2 ($C100/$C200), 80-Column Display ($C300), Mouse ($C400), and Disk II ($C600).

$E000–$F7FF: Applesoft ROM

Microsoft / Marc McDonald BASIC token parser, expression evaluator, and Hi-Res graphics math runtime.

$F800–$FFFF: System Monitor

Steve Wozniak / Allen Baum autostart reset vector, COUT character I/O ($FDED), and hex debugger.

Building Custom Firmware & Patching Vectors

When building custom ROMs for the Apple //c Ultra, three mandatory hardware vectors must be linked at the very top of memory ($FFFA–$FFFF): 

.ORG $FFFA
        .WORD NMI_HANDLER   ; $FFFA-$FFFB: Non-Maskable Interrupt
        .WORD COLD_BOOT     ; $FFFC-$FFFD: RESET Vector (Executed on Power-Up & RESET button)
        .WORD IRQ_HANDLER   ; $FFFE-$FFFF: Maskable Interrupt / BRK instruction

COLD_BOOT:
        SEI                 ; Disable interrupts
        CLD                 ; Clear decimal mode
        LDX #$FF
        TXS                 ; Initialize stack pointer to $01FF
        STA $C051           ; Set Text Mode ($C051 TXTSET)
        STA $C054           ; Page 1 Video ($C054 PAGE2 off)
        JSR $FC58           ; HOME: Clear screen
        ; Jump to Custom Ultra Diagnostics or ProDOS Bootloader
        JMP $2000

Modern Languages on 65C02 Silicon: The AOT Pipeline

Zero-Page virtual register architecture, portable class libraries, and vertical execution traces

Zero-Page Virtual Register Allocation ($80–$8F)

Modern managed runtimes (CLR & JVM) expect 32-bit registers and stack evaluation. The 65C02 has only an 8-bit Accumulator, X, and Y register. The AOT compiler bridges this by dedicating Zero-Page locations $80–$8F as virtual machine registers:

$80–$81 (R0) Primary 16-bit Accumulator & Return Value
$82–$83 (R1) Secondary Operand / Method Argument 0
$84–$85 (R2) Loop Counter & Dynamic Index Pointer
$86–$87 (OBJ) Current Object this Pointer in Heap
