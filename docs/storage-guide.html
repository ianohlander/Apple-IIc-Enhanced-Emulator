1

5.25" Disk II Floppy Subsystem & 6-and-2 GCR Nibblization

The Apple //c Ultra faithfully emulates Steve Wozniak's 1978 Disk II controller in Slot 6 ($C600). To prevent bit-slip errors on magnetic media without costly hardware PLL chips, Woz devised 6-and-2 Group Code Recording (GCR), converting 256 user data bytes into 342 6-bit disk nibbles ($96–$FF).

Physical Sector Framing
  • • Address Prologue: $D5 $AA $96
  • • Address Payload: Volume, Track (0–34), Sector (0–15), Checksum
  • • Address Epilogue: $DE $AA $EB
  • • Data Prologue: $D5 $AA $AD
  • • Data Payload: 342 GCR bytes + XOR Checksum
  • • Data Epilogue: $DE $AA $EB
4-Phase Stepper Motor ($C0EC–$C0EF)

The read/write head is positioned across 35 physical tracks (tracks 00–34) by cycling 4 phase softswitches: Phase 0 ($C0E1) → Phase 1 ($C0E3) → Phase 2 ($C0E5) → Phase 3 ($C0E7).

Boot Floppy: Type PR#6 in the interactive immediate prompt.
2

SmartPort 32MB Virtual Hard Disk (/HD)

The Apple //c Ultra implements the Apple SmartPort firmware protocol connected to an extended 32 Megabyte virtual volume (/HD) in Slot 7 ($C700). The storage volume is partitioned into 65,536 contiguous 512-byte logical blocks ($65,536 imes 512 = 33,554,432 ext{ bytes}$).

Block Range Volume Content Structure / Significance
Blocks 0 & 1 Bootloader Stage-1 ProDOS bootloader executed on PR#7.
Blocks 2..5 Volume Directory Header Key block 2 containing /HD name, timestamps, and bitmap pointers.
Blocks 6..37 Volume Allocation Bitmaps Bit allocation map: 1 bit per 512B block (65,536 bits = 32 blocks).
Blocks 38..65,535 User Files & Subdirectories Seedling (≤512B), Sapling (≤128KB), and Tree (>128KB) files.
3

Slinky 1MB Auxiliary RAM Disk (/RAM)

The Apple //c Memory Expansion Card ("Slinky") provides 1,048,576 bytes of fast banked memory accessed via 24-bit auto-incrementing registers at $C0C8..$C0CB (or $C071–$C075). Streaming 512 bytes of data requires zero bus wait-states, enabling instant audio and graphics texture paging. 

; Stream 512 bytes from Slinky RAM Disk into Video VRAM ($2000)
  LDA #$00 : STA $C0C8       ; Address Low = $00
  LDA #$02 : STA $C0C9       ; Address Mid = $02
  LDA #$00 : STA $C0CA       ; Address High = Bank 0
  LDY #$00
PAGING_LOOP:
  LDA $C0CB                  ; Read byte (Hardware auto-increments address!)
  STA $2000,Y                ; Store into video buffer
  LDA $C0CB                  ; Read next byte
  STA $2100,Y
  INY
  BNE PAGING_LOOP            ; Full 512-byte transfer completes in microseconds!

4.1 The Object-Oriented Mental Model vs. 65C02 Hardware Storage Reality

Modern application developers expect structured types, strings, byte arrays (byte[]), streams (FileStream, FileOutputStream), and hierarchical pathnames (such as /HD/SAVES/SLOT1.DAT). However, 65C02 silicon possesses only an 8-bit accumulator ($A$), two 8-bit index registers ($X, Y$), a 256-byte stack ($0100–$01FF), and communicates with storage controllers exclusively through 512-byte raw logical blocks and ProDOS Machine Language Interface (MLI) parameter packets.

4.2 C# .NET Core Storage API: Class Reference & Specifications

The Apple //c Ultra standard library for C# provides two primary namespaces for storage access: Apple2.Ultra (for high-performance hardware block I/O) and System.IO (for file and stream abstractions).

AppleStorage.UnitSlot6Drive1 const int = 0x60 Immediate constant #$60 Unit identifier for Disk II 5.25" Floppy Drive 1 (140 KB).
AppleStorage.UnitSlot4RamDisk const int = 0x40 Immediate constant #$40 Unit identifier for Slinky 1MB banked RAM Disk (/RAM).

4.4 Step-by-Step AOT Lowering Trace: From High-Level Call to 65C02 Assembly

Let's trace exactly how the AOT compiler lowers a high-level block write call into native machine code.

1. High-Level Source (C# & Java) 
// C# High-Level Block Write Call:
byte[] payload = new byte[512];
payload[0] = 0x41; // 'A'
payload[1] = 0x50; // 'P'
payload[2] = 0x50; // 'P'
payload[3] = 0x4C; // 'L'
payload[4] = 0x45; // 'E'
AppleStorage.WriteBlock(AppleStorage.UnitSlot7Drive1, 100, payload);
2. Generated 65C02 Machine Assembly 
; --- AOT Generated ProDOS MLI Block Write ---
       ; 1. Assemble MLI Parameter List at $0800
       LDA #$03        ; Param Count: 3
       STA $0800
       LDA #$70        ; Unit: Slot 7 Drive 1 ($70 = /HD)
       STA $0801
       LDA #$00        ; Buffer Pointer Low ($00)
       STA $0802
       LDA #$40        ; Buffer Pointer High ($40 = $4000)
       STA $0803
       LDA #$64        ; Block Number Low (100 = $0064)
       STA $0804
       LDA #$00        ; Block Number High ($00)
       STA $0805

       ; 2. Call SmartPort Block Driver Vector
       LDA #$70        ; Pass Unit Number in Accumulator
       LDX #$00        ; Parameter list low ($00)
       LDY #$08        ; Parameter list high ($08 = $0800)
       JSR $C700       ; Call Slot 7 SmartPort Driver
       BCS IO_ERROR    ; If Carry set, error occurred (code in A)
       RTS             ; Success: 512 bytes committed to /HD!

4.5 Production Architectural Patterns & Real-World Recipes

🕹️ Recipe 1: Game State & High Score Persistence (C#) C# .NET

Save player high scores, levels, and initials into a dedicated 512-byte block on the 32MB hard disk with XOR checksum integrity verification: 

using System.IO;
using Apple2.Ultra;

public class HighScoreManager {
    private const int SCORE_BLOCK = 100; // Block 100 on /HD

    public static void SaveHighScore(string initials, int score, int level) {
        byte[] buffer = new byte[512];
        
        // Header signature: "HI"
        buffer[0] = (byte)'H';
        buffer[1] = (byte)'I';
        
        // Initials (3 bytes)
        buffer[2] = (byte)initials[0];
        buffer[3] = (byte)initials[1];
        buffer[4] = (byte)initials[2];
        
        // Score (24-bit Little Endian)
        buffer[5] = (byte)(score & 0xFF);
        buffer[6] = (byte)((score >> 8) & 0xFF);
        buffer[7] = (byte)((score >> 16) & 0xFF);
        
        // Level
        buffer[8] = (byte)level;

        // Calculate XOR checksum
        byte checksum = 0;
        for (int i = 0; i < 9; i++) checksum ^= buffer[i];
        buffer[9] = checksum;

        // Commit directly to SmartPort 32MB Hard Disk Block 100
        AppleStorage.WriteBlock(AppleStorage.UnitSlot7Drive1, SCORE_BLOCK, buffer);
    }
}
🗺️ Recipe 2: Streaming World Tilemaps & Textures from /HD (C#) Asset Streaming

Stream massive 16KB RPG dungeon maps dynamically into auxiliary RAM without frame stuttering: 

using Apple2.Ultra;

public class MapStreamer {
    // Stream 32 contiguous blocks (16 KB) starting at block 200
    public static void LoadDungeonFloor(int floorNumber, byte[] targetMemory) {
        int startBlock = 200 + (floorNumber * 32);
        
        for (int b = 0; b < 32; b++) {
            byte[] blockData = AppleStorage.ReadBlock(AppleStorage.UnitSlot7Drive1, startBlock + b);
            // Copy 512 bytes into target memory buffer
            for (int i = 0; i < 512; i++) {
                targetMemory[(b * 512) + i] = blockData[i];
            }
        }
    }
}
⚡ Recipe 3: Slinky 1MB RAM Telemetry Ring Buffer with Persistent HD Commit (Java) Java 17

Log sensor samples to ultra-fast Slinky 1MB RAM disk in real-time, then batch-flush to 32MB hard disk when the 512-byte page fills: 

import apple2.hardware.AppleStorage;

public class HighSpeedTelemetry {
    private static byte[] pageBuffer = new byte[512];
    private static int bufferIndex = 0;
    private static int currentBlock = 300;

    public static void logSample(int timestamp, int voltage, int current) {
        pageBuffer[bufferIndex++] = (byte)(timestamp & 0xFF);
        pageBuffer[bufferIndex++] = (byte)(voltage & 0xFF);
        pageBuffer[bufferIndex++] = (byte)(current & 0xFF);

        // When 512-byte page buffer fills, commit to /HD and reset index
        if (bufferIndex >= 510) {
            AppleStorage.writeBlock(AppleStorage.UNIT_SLOT7_DRIVE1, currentBlock++, pageBuffer);
            bufferIndex = 0;
        }
    }
}
🛡️ Recipe 4: Robust Fault-Tolerant Storage Error Handling (C#) Error Handling

Inspect ProDOS MLI return codes and recover gracefully if media is write-protected or unavailable: 

using Apple2.Ultra;

public class StorageSafety {
    public static bool TryWriteSafely(int unit, int blockNum, byte[] data) {
        int status = AppleStorage.GetStatus(unit);
        if (status != 0) {
            AppleVideo.Print("ERROR: DRIVE OFFLINE OR UNATTACHED\n");
            return false;
        }

        int result = AppleStorage.WriteBlock(unit, blockNum, data);
        if (result == 0x2B) {
            AppleVideo.Print("ERROR: WRITE PROTECTED DISKETTE\n");
            return false;
        } else if (result != 0) {
            AppleVideo.Print("ERROR: MLI I/O FAULT CODE: $" + result.ToString("X2") + "\n");
            return false;
        }

        return true;
    }
}
